This milestone **closes one full bank**, not just a small source fragment.
Newly owned bank6 bytes include 7,408 byte-lane graphics, 1,520 tile indices,
241 bytes of count-prefixed layouts, 16 bytes of layout pointer directories and
7 bytes of padding. No new byte counts are ascribed to the already reconstructed
7,192-byte sprite/object code and primary records.

## System-level evidence

* The fixed bank0 assembly has literal references `$9C18` (visual resource)
  and `$BA5B` (second layout pointer directory). `wholebank06/asset_ledger.json`
  records these without inventing mapper-time execution evidence.
* The existing sprite producer-to-VDP bounded Z80 execution suites are still
  mandatory; Phase19 tested 192 record/origin combinations and Phase20 exercised
  the alternate object handler for another 192 scenarios.
* The static Z80 graph is unchanged because the 9,192 new bytes are sourced as
  data rather than newly recovered instructions. Existing three-bank graph
  snapshots remain valid and are part of full verification.
* Third-party `wla-z80`/`wlalink` fixtures can be **prepared** for all four
  banks. Real WLA compilation and full-game emulator traces remain **unverified**.
* The remaining twelve physical banks still need the original-ROM fallback.
  Even the four byte-complete banks include semantically unresolved data.

## Required gates

```sh
cd Ys
make four-bank-source
make bank06-source
make bank06-assets-verify
make four-bank-rom-verify ROM='/path/to/Ys.sms'
make system-m4-verify ROM='/path/to/Ys.sms'
make four-bank-wla-prepare
```

`make four-bank-wla-verify` intentionally fails if real assembler/linker
executables are not installed. It must never print a success status based
solely on fixture generation or the in-project Z80 encoder.
