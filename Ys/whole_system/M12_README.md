# Whole-System M12 — External Z80 encoding across the source cartridge

**Baseline:** All 16 physical ROM banks remain source-backed and produce an exact
262,144-byte cartridge with SHA-256
`02e9404e81bddd4ca21fef2b2711dfe562c3bd7b230bf042df3142362e29a6a9`.
No new source-backed ROM bytes are claimed at this milestone.

## New independent verification

The owner-provided **Emulicious.jar** (SHA-256 recorded in
`emulicious_assembler_report_m12.json`) includes an independent Z80 assembler,
`assembler.Z80Assembler`. The project adapter compiles a short Java bridge outside
Git and submits each mnemonic from the complete-bank source listings. The
third-party assembler determines the opcode; the Java bridge serializes its
instruction descriptors, including prefixes, index displacements and relative
branches. The resulting bytes are compared directly with the source-built
cartridge. A separately supplied original ROM is hash-checked when available.

The existing in-project encoder is used to locate instruction start positions
and lengths **only**; it is not used to produce the external assembler's bytes.
The input source is never rewritten to use DB opcode literals for this test.

- **11,009 instructions submitted** from 10 code-bearing banks.
- **22,552 instruction bytes independently encoded and matched.**
- **Zero mismatches; zero unsupported mnemonic syntaxes.**
- The other six physical banks' current mixed sources have no instruction
  mnemonics. Their DB/DW representation is not externally assembled here.
- Source-only full cartridge SHA-256 remains exact. No non-ROM source file or
  binary generated by the external tool is committed to Git.

This is a **real external instruction-level assembly comparison**, not merely
fixture preparation. It is **not** an independent 16-bank linker build. WLA-DX
v10.7 is still blocked by local DNS/network access to its public repository;
its Windows PE release archives cannot be run as native Linux executables.
The emulator boot/render smoke test from M11 remains the actual emulator
runtime evidence, not comprehensive gameplay verification.

## Reproduction

```sh
cd Ys
make source-cartridge-check  # no original ROM required
make emulicious-assembler-tests
make emulicious-assembler-verify \
  EMULICIOUS_JAR=/outside/git/Emulicious.jar \
  ROM='/outside/git/Ys - The Vanished Omens (USA, Europe).sms'
make system-m12-verify \
  ROM='/outside/git/Ys - The Vanished Omens (USA, Europe).sms' \
  EMULICIOUS_JAR=/outside/git/Emulicious.jar
```

`--external-jar` is optional for the historical runner; when provided it is a
mandatory fail-closed external verification gate. Without it, the tests check
stored evidence and invariants but do **not** claim a fresh assembler run.
