# Phase 19 — Bank-6 producer → RAM sprite buffers → SAT execution

**ROM:** Ys: The Vanished Omens (USA/Europe), 256-KiB SMS. ROM fingerprint is maintained in `../manifest.json`. **Scope:** a bounded, fail-closed instruction interpreter running original ROM bytes under *synthetic, controlled* RAM initial conditions. Not a gameplay trace or complete SMS emulator.

## What is newly verified

The preceding phases verified the separate operations: bank-6 record parsing (Phase 11B), fixed-bank SAT upload assembly (Phase 12), and VDP transfer execution with seeded RAM (Phase 18). Phase 19 connects these operations **in the same emulated RAM and CPU-memory environment**:

1. Execute fixed bank `$26F3` through `$270F`: `LD A,$06; LD ($FFFF),A` selects physical bank 6 in cartridge slot 2; write `$DD40` to RAM pointer `$C02A`, `$DD00` to `$C028`; `CALL $9932` enters the selected bank. The caller then writes `$D0` at the end of the Y-coordinate stream and clears `$C100`.
2. Execute bank 6 `$9932` from the actual ROM: read directory index at `$C199`, fetch a little-endian pointer from CPU `$8000 + index*2`, read count/delta/pair data, write one accumulated byte per entry to the first RAM destination and two bytes per entry to the second. The Z80 `LDI` decrements `BC` while copying the literal byte of each pair.
3. Compare `$DD00–$DD3F` and `$DD40–$DDBF` against an independent record decoder with three pairs of synthetic initial origins (`$C210/$C211`): `(0,0)`, `(17,29)`, `(240,250)`. Every record has 27–38 entries, so it fits in the two SAT arrays, and the caller's `$D0` terminator stays within `$DD00–$DD3F`.
4. Without copying or replacing RAM buffers, run the original SAT upload routine at fixed bank `$0427` in the *same interpreter state*. Check the actual port-$BF words `$7F00`/`$7F80`, all 192 writes to port `$BE`, their destinations `$3F00–$3F3F` and `$3F80–$3FFF`, and output digests. Fixed-bank `$0427` executes 206 supported instructions per invocation.

| Metric | Verified outcome | Interpretation |
|---|---:|---|
| Bank-6 directory entries | 64 | Previously decoded data, not newly found |
| Tested synthetic coordinate-origin pairs | 3 | 192 distinct execution cases |
| End-to-end bounded producer/SAT runs | **192** | Actual ROM opcodes, controlled state |
| SAT data bytes per run | 192 | 64 Y values + 128 X/tile values |
| Total SAT data bytes emitted | **36,864** | Sum across separate executions; not simultaneous VRAM capacity |
| New Phase 19 regression tests | **18** | Source/ROM mutations and independent calculations |
| New ROM classification/source-backed bytes | **0 / 0** | Existing source-backed total unchanged |

`execution_report.json` stores 192 hash-only case records (output hashes, executed instruction counts, source record indices, mapper value, origins, RAM-pointer endpoints) and a digest of all SAT outputs concatenated in test order. It does **not** store SAT payload arrays or any ROM image.

## Confidence and boundaries

**Verified by bounded ROM instruction execution:** The `$26F3` caller selects bank 6; `$9932` transforms the 64 input record variants into the predicted RAM arrays and advances both pointers; `$0427` subsequently writes those generated bytes to the two expected VDP SAT ranges. Three varied origin pairs verify nonzero offsets and 8-bit wraparound. Mutation tests reject wrong ROMs, corrupted executable opcodes, incorrect bank mapping, unsupported instructions, and execution-budget exhaustion.

**Not yet verified:** Full-system/emulator gameplay observation; whether these specific index/origin combinations arise in a game session; display mode, sprite renderer output or frame timing; Z80 flags/cycle accuracy outside the executed path; external Z80 assembler equivalence. The harness supports only the necessary opcodes and models VDP port `$BF/$BE` writes; all unknown opcodes fail closed. For historical Phase 18 limitations, see `../phase18/README.md`.

## Reproduce

```sh
python Ys/tools/phase19_sprite_execution.py '/path/to/Ys.sms' --check
python Ys/tests_phase19.py '/path/to/Ys.sms'
python Ys/tools/build_phase17.py '/path/to/Ys.sms' --verify
```

To deliberately regenerate the report while developing, run `--write` instead of `--check` and review the diff; do not use regeneration as a substitute for independently computed test expectations.

## Regression runner improvement

`tools/run_regressions_phase19.py` runs each historical phase independently,
with a configurable per-suite timeout and correct command-line contracts for
Phases 14/15 (which do not take a ROM argument). It includes Phase 11B,
the function-level matching workflow and the exact full-ROM overlay check.
A failed or timed-out suite produces a failing exit status; no suite is marked
passing unless the command returns successfully.

```sh
python Ys/tools/run_regressions_phase19.py '/path/to/Ys.sms' --timeout 120
# Targeted runs:
python Ys/tools/run_regressions_phase19.py '/path/to/Ys.sms' --suite phase18 --suite phase19
```
