# Phase 10B — bank-separated, byte-identical Z80 mnemonic assembly

## Results

**Status: PASS** on the exact source ROM identified in `Ys/manifest.json`.

- Repaired Phase 10A's `IndentationError` and a DD/FD-CB opcode placement defect.
- Fixed the missing indexed `ADD IX/IY,rr` variants and the ambiguous `RLD` versus `RL D` normalization.
- Independent (in-project) Z80 mnemonic encoder assembled **4,960 instructions / 10,188 distinct ROM bytes** from Phase 5–8's previously recovered instruction listings.
- Physical banks recovered in this source subset: **0, 1, 2, 4, 7, 8, 10, 12**. All offsets and generated bytes were independently checked against the original 256-KiB ROM.
- Phase 9B had **111 already assembler-matched bytes**, **61** of which overlap the new source set. **Union: 10,238 unique ROM offsets** (3.91% of ROM) supported by in-project assembler output.
- **0 new ROM bytes discovered/classified**. Previously reported *candidate* classification stays **37,748 / 262,144 bytes (14.40%)**, of which significant data remains provisional.
- All **ten** regression suites (Phases 1–9B and 10B) pass, including new altered-ROM, altered-source, altered-listing, mapping, duplicate-span and opcode-vector rejection checks.

## Source and verification model

- `src/phase10_roundtrip/bankNN.asm` is actual mnemonic assembly generated from independently recorded Z80 instruction starts, with `org` directives retaining the original CPU-relative address and comments showing the **physical ROM offset**. Code is **sparse**; its gaps are intentionally not filled with assumed instructions or original bytes.
- `tools/z80_roundtrip_phase10.py` is a *restricted in-project encoder*, not a third-party standard assembler. It emits opcodes from a separate instruction grammar; it does not read the ROM to obtain opcode bytes. It supports the audited forms exercised by this phase and rejects unsupported input.
- `tools/rebuild_phase10.py` separately verifies each instruction against (a) its recorded listing bytes, (b) the original ROM, and (c) the generated source assembled at its bank-relative address. It also rejects overlapping original-ROM instruction ranges and incorrect slot mappings.
- `tests_phase10.py` uses `tools/z80_regions.py` as a separate original-ROM instruction-length check for all **4,960** decoded starts, and uses independently selected opcode vectors to catch normalization and DD/FD/CB regressions.
- `phase10/roundtrip_report.json` records the per-bank counts and unique-overlap accounting; it is regenerated from the original ROM and checked for exact reproducibility.

## Reproduce

```bash
python Ys/tools/rebuild_phase10.py "/path/to/Ys - The Vanished Omens (USA, Europe).sms" --check
python Ys/tests_phase10.py "/path/to/Ys - The Vanished Omens (USA, Europe).sms"
```

To regenerate rather than check the bank-source snapshots, run `rebuild_phase10.py ... --write`. Use the Phase 1–9 commands from their respective technical reports for the earlier suites.

## Limitations and next steps

1. **No independent external assembler comparison** (`z80asm`, `sjasmplus`, `pasmo`, etc.) has yet been performed. The in-project encoder remains a distinct testing target, not confirmation of general Z80 assembly syntax compatibility.
2. The matching units come from existing **statically classified** instruction regions. They are not all emulator-observed execution paths; some bank/mapper assignments are explicitly conditional.
3. Original symbols, linker segments, contiguous binary reconstruction, sound-stream grammar, and runtime equivalence remain unresolved.
4. The encoder's preliminary support for arbitrary user-authored forward labels is **not certified** in this phase. Generated code uses literal hexadecimal targets, and a separate Phase 9B assembler retains the verified hand-labeled routines.
5. Next: test the same source under an independently installed external Z80 assembler; identify runtime-selected banks; introduce named symbols without altering instruction bytes; then expand verified assembly coverage to newly decoded code (rather than merely increasing provisional opaque data).

The commercial ROM and binary opcode dumps are excluded from the repository archive.
